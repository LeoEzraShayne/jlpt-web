# 账号与数据删除申请入口及人工处理核验

日期：2026-09-13。范围：Web `/delete-account`、个人页、隐私页和公共页脚。

## 已实现与尚未验证

本次只提供中英文公开说明和 `mailto:contact@meritledger.org` 按钮。无需登录或重装应用，用户自行填写、检查并发送邮件。页面不向后台提交申请，不收集额外资料，不执行删除，也不报告处理完成。

邮箱来源为既有公开渠道：[旧服务隐私政策](https://official.meritledger.org/privacy-policy)及[旧服务删除说明](https://official.meritledger.org/delete-account)。主代理于 2026-09-13 通过浏览器读取确认：旧服务提供应用内删除入口；无法登录者可联系该邮箱，经归属验证协助处理。旧服务说明不构成新 JLPT 数据库已支持删除的证据。

**本入口不能作为“完整账号删除功能已实现”或“Play 删除要求已经通过”的验收依据。** 尚需运营核验：邮箱负责人是否实际接收、识别并处理 JLPT 请求；新服务每类数据的执行方法、必要保留范围、备份及供应商处理方式；端到端合成账号演练结果。代码中没有新增自助删除 API、工单系统或自动邮件发送器。不能将旧服务删除接口直接用于新 JLPT 数据库。

## 拟采用的人工处理步骤（待运营确认与演练）

1. 收到邮件后在受控工作记录中登记申请。以注册 Google 邮箱提出请求为优先路径，核验账号归属及真正请求人。邮箱地址或公开资料单独不能当作充分证明；无法使用注册邮箱时，由获授权人员采取适当的替代验证。不得索取密码、验证码、完整银行卡信息或不必要的身份证件；不得把申请内容贴到公开 issue。
2. 确认服务范围：JLPT 日语学习、旧功过格，或两者。两套服务分别定位账号、处理并回报结果。先核实删除是否影响仍有价值的学习记录或购买权益，再明确处理范围；不把退出登录、解除设备绑定或旧 App 的删除提示当作新服务已删除。
3. 由获授权执行人员为该请求制定可审查的数据清单。JLPT 需覆盖账号资料、Google 账号关联、Web 与原生会话、学习计划、造句及批改、词汇与导入、进度和复习记录，以及关联任务、AI 使用记录、广告奖励记录等。按实际 schema 和数据关联逐项核对，不能只删除 `User` 后假设全部级联。付款订单、权益、额度和使用记录存在以字符串 userId 关联的独立记录，需明确删除或去标识处理。
4. 执行前确定进行中的学习任务、支付回调及奖励回调如何处置，防止处理后重新写入可关联的资料。确定需要停用的会话、任务和账号入口，评估再次使用 Google 登录是否重新创建新账号及其数据行为。本次变更未实现这些机制，不能以此文档替代实现或验证。
5. 区分需删除的数据与必要保留记录。对确需保留的交易、安全或争议记录，记录实际目的、最小字段、访问范围与适用保留期限，并向申请人说明。不要泛称所有付款数据永久保留，也不要承诺删去 Google、Stripe 或 AI 供应商所持有的全部副本。备份轮换、恢复后处理及第三方请求能力应分别核实；没有证据时标为待确认，不给固定 SLA。
6. 使用已核准的方法执行并复核，记录实际结果、保留项目和未完成事项。仅在验证后告知申请人处理结果；收到邮件或进入队列不能发“已删除”。若两服务状态不同，要分别说明。人工回复由获授权人员发送，本页面及本次任务不会自动发送。
7. 如涉及旧服务订阅，告知发送删除申请不会自动取消订阅，按原服务的订阅管理流程单独核实；不得声称新 JLPT 一次性通行证存在自动续费。

## 发布与运营验收分开

前端验收：未登录可访问 `/delete-account`；中英文正文和文档标题正确；个人页、隐私页和页脚可到达；邮件按钮仅打开用户邮件客户端，收件人为已公开邮箱，主题及正文不自动携带当前账号资料；未配置邮件应用时能复制邮箱。不得模拟一次点击后显示成功或发起删除请求。

运营验收：确认有权处理 JLPT 请求的负责人和接收渠道，以专用合成账号演练归属核验、两服务范围区分、会话与任务处置、逐项删除/去标识及必要保留、结果复核和通知。用匿名化证据记录完成状态；不得放入真实用户资料、邮件正文、令牌或生产凭据。未完成此演练前，商店材料只能说明存在删除申请渠道，不能声称完整删除流程已经验收。

本次无需也未访问真实邮箱、发送邮件或删除任何用户数据。部署由主代理单独评审执行。
